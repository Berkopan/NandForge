# Educational and interface design references

**Review date: 2026-10-17.** This is a late reference check made after NandForge's initial implementation and functional verification. It records relevant ideas from primary project sources and relates them to decisions already present in this repository. It does not claim that this research preceded implementation, and it makes no comparative performance or learning-outcome claims.

The reviewed material was official project documentation, the maintainers' repository README, or the developer's product description. No competitor code, screenshots, icons, lesson prose, or other assets were imported during this review.

## Decisions implemented here

NandForge uses a single typed `Circuit`/`ChipDefinition` model for the editor, user chips, Academy and generated CPU. The compiler expands hierarchy into actual NAND operations and declared primitive state/memory boundaries. The CPU follows the brief's nineteen-instruction eight-bit architecture, with its own decoder, control equations, assembler, flags and examples. [Canonical model](../src/core/types.ts), [NAND blueprints](../src/core/chips.ts), [CPU graph](../src/cpu/architecture.ts), [ISA](ISA.md).

Inspection reads the same simulator instance at the selected hierarchical path, so two instances of a register chip can show different stored values. Behavioral challenge checks exercise outputs and clock sequences; arbitrary cosmetic names or a familiar component arrangement cannot establish a correct result. These choices are backed by execution tests. [Editor runtime](../src/editor/useCircuitRuntime.ts), [Academy verifier](../src/academy/verify.ts), [instance inspection tests](../tests/editor/model.test.ts), [challenge tests](../tests/academy/verify.test.ts).

The product combines English/Turkish lessons, local project storage, a fixed inspectable computer, bounded waveform/history recording and static `/NandForge/` hosting. Those are scope decisions for this implementation. They do not establish feature parity with any referenced tool. [Architecture](ARCHITECTURE.md), [simulation boundaries](SIMULATION.md), [current acceptance evidence](IMPLEMENTATION_STATUS.md).

## Limits of this check

This review inspected the cited primary descriptions. It did not conduct a usability study, benchmark another simulator, play through another product's complete curriculum, or audit another project's source implementation. It therefore supports the narrow educational and interface observations above, without rankings, claims of superiority, or assumptions about unexamined capabilities.
